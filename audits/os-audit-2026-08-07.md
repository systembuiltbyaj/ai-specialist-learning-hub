### Hole found during verification — the gate did not gate

The middleware redirect on `/interview` was **not** protecting the data. Those
pages are client components that imported their seed directly, so the content
was compiled into `/_next/static/chunks/app/interview/page-*.js` — a static URL
that middleware cannot match and that served the full contents to an
unauthenticated request. The redirect was cosmetic.

Fixed by moving `INTERVIEW_SEED`, the discovery playbook, and both presentation
scripts into the **server components**, passed down as props, so they travel only
in the gated RSC payload. Confirmed: 0 static chunks contain the markers, and
`/interview` shrank 12.1 kB → 5.68 kB, `/presentation` 9.83 kB → 6.43 kB.
Both routes still render fully for a signed-in admin.

**Residual risk to accept or close later:** anything rendered inside a client
component is reachable by whoever holds the chunk URL. The rule going forward —
*private data is imported in `page.tsx`, never in a `"use client"` file.*

### Next.js advisories — FOUND AND RESOLVED same day

`npm audit --omit=dev` reported **21 HIGH** advisories against `next@14.2.35`
(cache poisoning, SSRF in rewrites and Server Actions, XSS in App Router with
CSP nonces, several DoS vectors) plus 4 against its bundled `postcss`.

**Upgraded to `next@16.3.0`.** React stayed on 18 — Next 16 accepts `^18.2.0`,
so React 19 was not forced and the blast radius stayed small.

Breaking changes handled:
- `cookies()` is async → `await cookies()` in `app/lib/adminSession.ts`
- `params` is a `Promise` in pages and `generateMetadata` → both `[slug]` routes
- `middleware.ts` deprecated in favour of `proxy` → **deleted**, since it had an
  empty matcher and gated nothing

Verified after upgrade: **0 vulnerabilities**, 22/22 tests, 16/16 routes 200,
22/22 overlap redirects, sitemap 232, search index 257 records, 5 security
headers, admin auth + rate limiting intact (401×5 → 429). Build now runs on
Turbopack — compile time fell from ~20s to 6.5s.
