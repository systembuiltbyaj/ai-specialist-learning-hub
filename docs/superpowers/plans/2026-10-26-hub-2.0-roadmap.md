# AJ AI Learning Hub 2.0 — Implementation Plan

## Context

The Hub is a public, statically rendered Next.js 16 reference site. Its content is in two stores:
- `data/` holds the dictionary (133 terms) and the acronyms (106).
- `app/lib/seed/` holds everything else.

The content has drifted:
- The news archive stops at 2026-06-22.
- The Claude tiers say "Sonnet 5" and "Haiku 4.5" in several files; Anthropic's lineup is now on 5.5.
- `tools.ts` says "Opus 5" in two places and "Opus 5.5" in another.
- `webguide.ts:206` has a code sample with `claude-sonnet-4-6`.
- Seven files have no 2026 content at all: claude, automationhub, ghlhub, acronyms, discovery, interview, and the dictionary outside its tiers entry.

The structural causes:
- Model names are hardcoded in 5+ files.
- No item carries a source or a last-verified date.
- The last "weekly" feed was built but never connected to a scheduler, so it froze silently. An unverified model claim then sat on a public page.

**Goal:** a reliable, practical, regularly refreshed platform. That means:
- a verified glossary
- learning paths and a project library
- a news center that is refreshed manually, with an editorial gate
- light/dark mode
- a content architecture that shows its own staleness instead of hiding it

**Decisions locked with AJ:**
- **No scheduler.** Refreshes are manual. "Run discovery" is a button on an admin page; nothing runs on a clock.
- **Hybrid store.** Glossary, model registry, learning paths and projects stay in git as typed files, so git is the versioning and the PR is the review, and those pages stay static. Only news items, plus the new terms they suggest, go into Supabase with a draft, approved or rejected status.
- **Approved dependencies:** `zod`, `fast-xml-parser`, `@anthropic-ai/sdk`. `next-themes` was declined, so the theme toggle is an inline script; the CSP already allows `'unsafe-inline'` for scripts (`next.config.mjs:14`).
- **Order:** content refresh first, after the foundation cleanup.

**On the ChatGPT architecture:** the shape (sources → ingest → Claude → Supabase → Next.js) is sound for news, with two corrections.
1. **Claude does not verify facts.** Verification is deterministic: the source must be on an allowlist of official domains, the URL must resolve, and the date must come from the feed. Claude only summarizes the source text, and a human approves every item.
2. **The glossary and lessons stay in git.** Moving them to Supabase would cost static rendering, type safety and free versioning.

## Breaking changes / migrations
- **Dictionary entries gain new fields:** `simple`, `sources[]`, `lastVerified`, `status`, `supersededBy?`. All entries get backfilled. This is not a rename: `whyItMatters` stays and is displayed as "Practical use".
- **Model names move into `data/models.ts`.** `tools.ts`, `devtools.ts`, `webguide.ts` and the dictionary tiers entry stop hardcoding versions and read from it.
- **`/updates` → `/news`** with a 308 redirect. The `lh.updates.v1` localStorage archive and `SEED_UPDATES` are retired. The 14 June items are migrated only if they can be re-verified; the Fable 5 / Mythos export-control item is dropped unless a source is found.
- **New Supabase migration:** `news_items` and `ingest_runs` tables. `/news` moves from fully static to tag-revalidated.
- **Nav regroup** in `app/lib/constants.ts` `NAV_GROUPS`. URLs don't change apart from `/updates`.
- **Hex colours in `tailwind.config.ts` become CSS-variable tokens.** Class names stay the same, so existing components flip themes without edits.
- **Dead stores deleted** after a content diff:
  - `seed/terms.ts`, `seed/glossary.ts`
  - `GlossaryClient.tsx`, `TermCard.tsx`
  - `getTerms()`

## Milestones

Each milestone ships on its own. Each gets its own spec and plan in `docs/superpowers/{specs,plans}/` and runs Execute → Review → Verify.

### M0 — Foundation cleanup (small, prerequisite)
1. Content-diff the dead stores (`seed/terms.ts`, `seed/glossary.ts`) against `data/dictionary.ts`. Carry anything the dictionary lacks into the M1 backlog, then delete:
   - the two stores
   - `app/dictionary/GlossaryClient.tsx`, `app/components/TermCard.tsx`
   - `getTerms()` in `app/lib/data.ts`
2. Add `app/lib/content/schema.ts`: zod schemas for `DictionaryTerm`, `ModelEntry`, `Source {label, url}`, `ContentStatus = "current" | "emerging" | "deprecated"`.
3. Add `data/models.ts`, the **single model registry**. Each entry holds `{id, vendor, name, family, tier, releasedOn?, status, contextWindow?, pricingNote?, sources[], lastVerified}`.
   - Helper `modelName(id)` is used by the seed files instead of literal strings.
   - Pricing is held as a dated note with a source link, never as a bare number.
4. Add `tests/content.test.ts`. It runs the zod schemas over every dictionary term and model and asserts:
   - every `related` id resolves
   - every source URL is https
   - every `lastVerified` is an ISO date
   - every deprecated item has `supersededBy` or a note
5. Add `scripts/content-check.mjs` → `npm run content:check`. It reports items whose `lastVerified` is more than 120 days old, terms with no sources, and orphaned related ids. It is read-only.
6. Fix stale comments: `.env.example:22-25`, `app/interview/page.tsx`, and the "weekly cron" comment in `supabaseAdmin.ts:4`.

### M2 — Learning paths, projects, progress
- **`data/paths.ts`:** three paths (Beginner, Intermediate, Advanced) of lessons `{id, title, summary, sections[], termIds[], exercise, nextId?}`.
  - Lessons **reference** dictionary terms by id and never copy definitions.
  - Each lesson's quiz reuses `app/lib/quiz.ts` by scoping questions to `termIds`. That needs a small `buildQuiz({termIds})` option, with tests.
- **`data/projects.ts`:** the nine requested projects, each `{id, title, level, stack[], architecture[], prerequisites[], steps[], exampleWorkflow, testing[], termIds[], lastVerified}`.
- **Routes, all static:**
  - `/learn`, `/learn/[path]`, `/learn/[path]/[lesson]` with `generateStaticParams` and `dynamicParams = false`, the same pattern as `app/dictionary/[slug]/page.tsx`
  - `/projects`, `/projects/[slug]`
- **Client state** (per-browser, under the `lh.<feature>.v<n>` convention):
  - `lh.progress.v1`: completed lessons and project steps
  - `lh.bookmarks.v1`: term, lesson and project ids
- **`/me`:** a progress dashboard (client) with bookmarks and the recommended next lesson. The recommendation is deterministic: the next incomplete lesson in path order, via a pure function in `app/lib/progress.ts`, with tests.
- **Search:** lessons and projects are added to the search index, which covers `title`, `snippet` and `url` only.

### M3 — News center (manual discovery + editorial gate)
**Prerequisite:** check the Supabase env with read-only `vercel env ls`. If the project or keys are missing, stop and have AJ create the project.

- **Migration** `supabase/migrations/<date>_news.sql`:
  - **`news_items`:**
    - fields: `id, url unique, url_hash unique, title, company, category, published_at, summary, why_it_matters, applications text[], suggested_terms text[], source_domain, status (draft | approved | rejected), ai_draft jsonb, confidence, last_verified_at, reviewed_at, created_at, updated_at`
    - `ai_draft` keeps the original model output, so human edits stay auditable.
  - **`ingest_runs`:** `started_at, finished_at, fetched, inserted, duplicates, errors jsonb`.
  - **RLS:** anon can select `news_items` where `status = 'approved'`. All writes run on the service role only.
- **Sources:** `app/lib/news/sources.ts` is a git-reviewed allowlist of official RSS/Atom feeds with vendor and domain.
  - Vendors with no feed are listed as `manual` and added through the admin form.
  - Feed URLs get verified in M3. None are invented.
- **Pure modules in `app/lib/news/`, each unit-tested:**
  - `parse.ts`: RSS and Atom parsing via fast-xml-parser
  - `normalize.ts`: strip utm parameters and fragments, then hash the URL
  - `dedupe.ts`: exact match on `url_hash`, plus title-token Jaccard ≥ 0.8 within 14 days
  - `validate.ts`: zod check; the domain must be on the allowlist and the date can't be in the future
  - `summarize.ts`: calls `@anthropic-ai/sdk` with structured output and a model id from env `ANTHROPIC_MODEL`. The prompt allows only the item and source text; the output carries a `supportedBySource` boolean and a confidence score.
- **`POST /api/news/discover`:**
  - Guarded by `isAdmin()`, `rateLimit.ts` and an origin-header check. Sets `maxDuration`.
  - Supports `?dryRun=1`, which previews the run without writing.
  - Caps items per run.
  - A failure in one source is logged to `ingest_runs` and the run continues.
  - If Claude fails, the item is still saved as a draft, flagged "needs summary".
  - **Nothing is ever auto-published.**
- **`/admin/news`:** dynamic and noindex, gated by `isAdmin()`, with nothing from it in the global layout or Footer (Rule 1). Features:
  - the "Run discovery" button and the dry-run preview
  - the draft queue with edit, approve and reject
  - the last-run log
  - suggested terms, shown for a manual git add

  Approving an item calls `revalidateTag('news')`. Read `node_modules/next/dist/docs/01-app/01-getting-started/09-revalidating.md` and `08-caching.md` first, because the Next 16 caching APIs differ from older versions.
- **`/news`:** a server component that reads approved items through the anon client and hands them to `NewsClient`, which filters by company, category and date range. Every card shows the published date, last-verified date, summary, why it matters, applications and the official link.
  - If Supabase isn't configured, the page renders an honest empty state, following the `data.ts` fallback pattern.
  - `/updates` gets a 308 redirect to `/news`.
- **Home:** shows "Knowledge current through <date>", derived from the latest approved item and the max `lastVerified`. This replaces any cadence promise ("weekly") with an honest date.

### M4 — UI modernization
- **Theme tokens.** Convert the `tailwind.config.ts` colours (`bg`, `surface`, `surface-2`, `line`, `muted`, `text`, `gold`, `violet`) to `rgb(var(--x) / <alpha-value>)`. Define dark values (the current hex) and a light palette in `globals.css` under `[data-theme]` plus `prefers-color-scheme`.
- **No-flash theme.** An inline script in `app/layout.tsx` sets `data-theme` before paint from the `lh.theme.v1` key, and the toggle sits in the Sidebar.
  - Keep the toggle client-only and off the cookie path, so static rendering survives.
  - Check contrast of gold on a light background; gold is likely to need a darker light-mode shade.
- **Nav regroup** in `NAV_GROUPS`:
  - Learn: Home, Paths, Projects, Quiz, My Progress
  - Reference: Dictionary, Acronyms, Tools, Dev Tools, Web Guide
  - Hubs: Claude, GHL, Automation
  - News
  - Workspace: Interview, Tasks, Resources
- **Home dashboard:** continue-learning card, latest approved news, Term of the Day, global search.
- **Category filter chips** shared across dictionary, projects and news, reusing `.chip`.
- **Accessibility pass:** focus rings, landmarks, contrast in both themes, and `prefers-reduced-motion`. The cold open is already handled.
- **Reuse:** keep `IntroOverlay`, `SiteSearch`, `RefCard` and `SectionLabel`. No new animation.

## Risks
- **Manual cadence means the same freeze risk as last time.** Mitigation: staleness becomes *visible* through per-item `lastVerified`, `content:check` and the home "current through" date. There will be no "weekly" wording anywhere.
- **Research volume.** M1 is the biggest milestone. Unsourceable claims are cut, so the glossary may grow less than hoped.
- **Light-mode contrast** of the gold brand colour needs a separate light-mode shade.
- **Out of scope** unless asked: the broken ESLint setup, the unused `terms` table in `schema.sql`, the 749 KB logo.

## Verification (every milestone)
`npm test`, then `npm run build`, then check the route table for static vs dynamic. Run `npm run content:check` from M0 on. Then a browser walkthrough of the changed routes on `npm run start`, in both themes from M4 on. Nothing is committed or pushed without AJ's go-ahead.
